# 内部 AI API 统一接入平台 PRD

状态：Draft v0.1  
日期：2026-10-09  
产品定位：内部平台  
目标读者：产品、研发、运维、财务/成本管理、业务接入方

## 1. 文档目标

本文档定义一个内部 AI API 统一接入平台的产品需求。该平台面向公司内部业务系统，整合多个 AI API 渠道，对内提供统一、稳定、可观测、可控成本的 API 暴露能力。

平台重点解决 6 类问题：

1. API 健康度管理
2. API 消耗量管理
3. API 成本管理
4. 多合一 API 统一包装暴露逻辑
5. 渠道不掺水探针，持续发现渠道退化或失效
6. 告警管理，尤其是异常大额消耗告警

## 2. 背景与问题

当前 AI 能力通常来自多个上游渠道，不同渠道在协议、模型、价格、稳定性、限流策略、错误格式、计费口径、响应质量上存在差异。业务系统如果直接对接多个渠道，会产生以下问题：

- 接入成本高：每个业务都要理解不同上游 API 协议。
- 稳定性不可控：单个渠道故障、限流、余额不足、模型不可用时，业务难以及时切换。
- 成本不可控：缺少按应用、渠道、模型、时间维度的消耗和成本归因。
- 风险发现滞后：渠道上线初期可用，但后续可能出现响应质量下降、鉴权失效、限流变更、隐性失败等问题。
- 告警不及时：异常大额消耗、错误率突增、探针失败等问题无法第一时间触达负责人。

因此需要建设一个内部统一平台，将多渠道能力包装为一致的内部服务层，并提供健康、用量、成本、探针、告警等治理能力。

## 3. 产品目标

### 3.1 核心目标

- 统一接入：为内部业务提供统一 API 入口，屏蔽不同上游渠道协议差异。
- 稳定可用：根据渠道健康度、权重、成本、限额等策略做路由选择和故障切换。
- 消耗可见：记录每一次 API 请求的输入、输出、token、图片、视频、调用次数等消耗指标。
- 成本可控：支持按应用、渠道、模型、能力类型、时间区间统计成本，并支持预算和阈值管理。
- 持续探测：通过不依赖业务流量的探针任务，持续验证渠道真实可用性和结果质量。
- 风险告警：对健康异常、消耗异常、成本异常、余额风险、探针失败等场景及时告警。

### 3.2 非目标

- 不直接建设模型训练、微调、评测平台。
- 不替代上游渠道自身的账号管理和商务采购系统。
- 不在首期提供面向外部客户的公开商业化 API 网关。
- 不在首期承诺对所有历史上游协议做 100% 字段兼容，优先覆盖内部业务高频使用字段。

## 4. 关键术语

| 术语 | 定义 |
| --- | --- |
| 应用 | 内部接入方，一个业务系统或服务。每个应用拥有独立凭证、权限、配额和成本归因。 |
| 渠道 | 一个上游 AI API 供应方、代理方、账号池或内部服务实例。 |
| 能力类型 | 文本、图片、视频等不同 AI 能力。 |
| 标准格式 | 平台对外暴露或内部归一化支持的一类 API 入参/出参协议。 |
| 模型映射 | 将内部模型名映射到一个或多个渠道模型名的配置。 |
| 路由池 | 一组可承接同类能力和模型的渠道集合。 |
| 健康度 | 平台对渠道可用性、稳定性、延迟、错误率、探针结果等指标的综合判断。 |
| 消耗量 | 请求次数、token、图片张数、视频秒数、任务数等可计量资源使用情况。 |
| 成本 | 基于渠道价格、消耗量、汇率/折扣/加价规则计算出的金额。 |
| 探针 | 平台主动发起的测试调用，用于确认渠道真实可用性和响应质量。 |

- OpenAI Completions 标准格式。
- OpenAI Responses 标准格式。

#### 图片能力

首期支持 3 种图片标准格式：

- gptimage 标准格式。
- nanobanana 标准格式。

#### 视频能力

首期支持 2 种视频标准格式：

- seedance 标准格式。
- minimax-h3 标准格式。

## 7. 核心流程

### 7.1 API 调用流程

1. 业务方使用应用凭证请求统一 API。
2. 平台完成鉴权、权限检查、限流和基础参数校验。
3. 平台识别能力类型、标准格式、模型名、业务应用、请求优先级。
4. 平台将请求转换为内部标准请求对象。
5. 路由引擎根据健康度、权重、成本、配额、限流、区域、能力匹配等因素选择渠道。
6. 协议适配器将内部标准请求对象转换为目标渠道请求。
7. 平台调用上游渠道，处理超时、重试、流式响应和错误。
8. 平台将上游响应转换回调用方请求的标准格式。
9. 平台记录请求日志、消耗量、成本、延迟、错误、渠道命中等数据。
10. 平台将响应返回给业务方。

### 7.2 渠道接入流程

1. 平台管理员创建渠道档案。
2. 配置渠道凭证、基础地址、能力类型、支持模型、并发限制、超时时间。
3. 配置模型映射、价格规则、路由权重、优先级、探针用例。
4. 执行连通性测试和探针测试。
5. 测试通过后加入路由池。
6. 观察灰度期指标，确认稳定后提升流量权重。

### 7.3 异常切换流程

1. 平台发现渠道错误率、超时率、探针失败率或余额风险异常。
2. 健康度评分下降，渠道进入降权、半开或摘除状态。
3. 路由引擎减少或停止向该渠道分配流量。
4. 告警系统通知负责人。
5. 渠道恢复后，平台通过探针和少量真实流量验证。
6. 验证通过后逐步恢复权重。

## 8. 功能需求

### 8.1 API 健康度管理

#### 8.1.1 目标

平台需要持续判断每个渠道、模型、能力类型的健康状态，并将健康状态用于路由选择、自动摘除、恢复和告警。

#### 8.1.2 健康指标

每个渠道至少采集以下指标：

- 成功率：按 1 分钟、5 分钟、15 分钟、1 小时窗口统计。
- 错误率：区分 4xx、5xx、超时、限流、鉴权、余额不足、内容安全拦截、响应解析失败。
- 延迟：P50、P90、P95、P99。
- 首 token 延迟：适用于流式文本接口。
- 任务完成耗时：适用于图片和视频异步任务。
- 限流情况：上游限流次数、限流恢复时间、并发占用。
- 探针结果：最近 N 次探针成功率、连续失败次数。
- 余额/额度状态：如渠道可提供余额查询能力，则采集余额和可用额度。
- 响应质量校验结果：探针返回是否满足基本语义和格式要求。

#### 8.1.3 健康状态

渠道健康状态分为：

| 状态 | 含义 | 路由行为 |
| --- | --- | --- |
| healthy | 健康 | 正常参与路由。 |
| degraded | 轻微退化 | 降低权重，继续少量使用。 |
| half_open | 半开恢复 | 仅允许探针和少量灰度流量。 |
| unhealthy | 不健康 | 从普通流量中摘除。 |
| disabled | 人工停用 | 不参与路由，需人工恢复。 |

#### 8.1.4 健康评分

健康评分建议采用 0-100 分：

- 成功率：35%
- 延迟：20%
- 错误类型严重度：15%
- 探针结果：20%
- 余额/额度风险：10%

首期可先实现规则式评分，后续根据历史数据优化权重。

#### 8.1.5 自动动作

- 当渠道连续超时或错误率超过阈值时，自动降权。
- 当渠道连续探针失败达到阈值时，自动摘除。
- 当渠道余额低于阈值时，自动停止或限制高成本请求。
- 当渠道恢复探针连续成功后，进入 half_open 状态。
- half_open 状态下验证成功后逐步恢复权重。

#### 8.1.6 页面需求

健康度页面需要支持：

- 渠道列表：状态、评分、成功率、错误率、延迟、最近探针结果。
- 渠道详情：按能力、模型、时间维度查看指标趋势。
- 异常事件时间线：记录状态变化、告警、人工操作。
- 手动操作：启用、停用、降权、恢复、立即探针。

### 8.2 API 消耗量管理

#### 8.2.1 目标

平台需要准确记录各应用在各能力类型、模型、渠道上的资源消耗，为成本计算、预算管理、业务分析和异常检测提供基础。

#### 8.2.2 消耗指标

文本接口至少记录：

- 请求次数。
- 输入 token。
- 输出 token。
- 总 token。
- 缓存命中 token，如上游返回。
- reasoning token，如上游返回。
- 流式/非流式标识。
- 成功/失败状态。

图片接口至少记录：

- 请求次数。
- 生成图片张数。
- 输入图片张数。
- 图片尺寸。
- 图片质量档位。
- 任务成功/失败状态。

视频接口至少记录：

- 请求次数。
- 生成视频数量。
- 视频时长。
- 分辨率。
- 帧率，如适用。
- 任务成功/失败状态。
- 任务排队时间、生成时间。

通用维度至少包括：

- 应用。
- 调用用户或业务标识。
- 渠道。
- 模型。
- 能力类型。
- 标准格式。
- 请求时间。
- 响应时间。
- trace_id/request_id。
- 路由策略命中原因。

#### 8.2.3 统计视图

平台需要提供以下统计视图：

- 实时用量：最近 5 分钟、15 分钟、1 小时。
- 日用量：按天汇总。
- 月用量：按自然月汇总。
- 应用用量排行。
- 模型用量排行。
- 渠道用量排行。
- 成功请求和失败请求分布。
- 峰值 QPS、并发数、排队数。

#### 8.2.4 数据准确性要求

- 所有进入统一网关的请求都必须产生调用记录。
- 成功请求必须记录真实上游返回的消耗量；若上游未返回，则使用平台估算值并标记为 estimated。
- 失败请求也必须记录，以便分析错误成本和重试成本。
- 需要支持幂等记录，避免重试导致重复计费。

### 8.3 API 成本管理

#### 8.3.1 目标

平台需要将消耗量转换为可归因、可分析、可预警的成本数据，帮助内部团队控制预算和优化渠道选择。

#### 8.3.2 价格配置

价格规则至少支持：

- 按渠道配置。
- 按模型配置。
- 按能力类型配置。
- 按输入 token、输出 token 分别配置。
- 按图片张数、尺寸、质量档位配置。
- 按视频时长、分辨率、模型档位配置。
- 支持免费额度、阶梯价、折扣价、固定加价。
- 支持币种和汇率配置。
- 支持价格生效时间，保留历史价格用于回算。

#### 8.3.3 成本计算

每次请求完成后生成成本明细：

- 原始消耗量。
- 渠道原始成本。
- 汇率换算成本。
- 内部结算成本，如需。
- 是否估算。
- 对应价格规则版本。

#### 8.3.4 成本分析

成本页面需要支持：

- 按应用查看成本。
- 按渠道查看成本。
- 按模型查看成本。
- 按能力类型查看成本。
- 按时间趋势查看成本。
- 查看预算使用率。
- 导出成本明细。
- 对比同一模型在不同渠道的单位成本和稳定性。

#### 8.3.5 预算控制

预算可以配置在以下层级：

- 平台总预算。
- 应用预算。
- 应用 + 能力类型预算。
- 应用 + 模型预算。
- 渠道预算。

预算动作包括：

- 仅告警。
- 降低优先级。
- 限流。
- 阻断非关键请求。
- 需要人工审批后继续使用。

### 8.4 多合一 API 统一包装暴露逻辑

#### 8.4.1 目标

平台需要对内暴露统一 API，同时支持多种标准格式，使业务方可以按已有调用习惯接入。平台内部通过标准请求对象和适配器完成协议归一、路由、转发和响应包装。

#### 8.4.2 协议设计原则

- 对外兼容多种主流/内部标准格式。
- 对内转换为统一内部标准请求对象。
- 路由逻辑不依赖某个上游协议特有字段。
- 响应尽量保持调用方所请求的标准格式。
- 上游错误需要转换为平台统一错误码，同时保留原始错误信息用于排查。

#### 8.4.3 内部标准请求对象

内部标准请求对象至少包含：

- ability_type：text/image/video。
- protocol：jev/openai_completions/openai_responses/anthropic_messages/gptimage/nanobanana/grok/seedance/minimax_h3。
- model：内部模型名。
- input：归一化后的输入内容。
- generation_config：温度、top_p、max_tokens、尺寸、时长等生成参数。
- stream：是否流式。
- attachments：图片、文件、音视频等输入资产。
- metadata：应用、用户、业务场景、trace_id、幂等键。
- policy：成本优先、质量优先、速度优先、指定渠道、禁止渠道等调用策略。

#### 8.4.4 路由选择逻辑

路由引擎需要根据以下因素选择渠道：

- 能力匹配：渠道是否支持能力类型、模型和标准格式。
- 健康度：健康渠道优先，不健康渠道摘除。
- 权重：支持按渠道设置基础流量权重。
- 优先级：支持主备优先级。
- 成本：在满足质量和健康要求下选择低成本渠道。
- 延迟：对实时场景优先低延迟渠道。
- 配额：避免使用已达到预算、额度或并发上限的渠道。
- 应用策略：不同应用可配置不同可用渠道和路由策略。
- 灰度策略：支持按比例、应用、用户、模型灰度。

#### 8.4.5 路由策略类型

首期建议支持：

| 策略 | 说明 |
| --- | --- |
| weighted_round_robin | 按渠道权重轮询。 |
| priority_failover | 优先使用主渠道，失败后切换备渠道。 |
| least_latency | 优先选择近期延迟较低渠道。 |
| cost_optimized | 在健康渠道中优先选择单位成本较低渠道。 |
| manual_pinned | 由调用方或配置指定固定渠道。 |

#### 8.4.6 重试和降级

- 支持按错误类型配置是否重试。
- 超时、5xx、连接失败可重试。
- 参数错误、鉴权失败、内容安全拒绝默认不重试。
- 重试需要避免对非幂等任务产生重复计费风险。
- 图片、视频异步任务需要区分“创建任务失败”和“任务执行失败”。
- 当目标格式或模型不可用时，可按配置降级到替代模型或替代渠道。
- 降级行为必须记录在调用日志中，并可由业务方选择是否允许。

#### 8.4.7 错误码归一

平台统一错误码建议包括：

| 错误码 | 含义 |
| --- | --- |
| auth_failed | 应用鉴权失败。 |
| permission_denied | 应用无权访问该能力、模型或渠道。 |
| invalid_request | 请求参数非法。 |
| rate_limited | 平台或上游限流。 |
| quota_exceeded | 应用额度或预算超限。 |
| upstream_timeout | 上游超时。 |
| upstream_error | 上游通用错误。 |
| upstream_unavailable | 无可用上游渠道。 |
| content_blocked | 内容安全拦截。 |
| response_parse_failed | 上游响应解析失败。 |
| cost_guard_triggered | 成本保护触发。 |

### 8.5 渠道不掺水探针

#### 8.5.1 目标

探针用于验证渠道真实可用性，而不是只检查接口是否返回 200。平台需要通过持续、独立、可校验的探针发现渠道退化、假成功、响应变慢、质量异常、成本异常等问题。

#### 8.5.2 探针原则

- 独立于业务流量：探针由平台主动发起，不依赖业务是否有真实调用。
- 覆盖真实能力：文本、图片、视频都要有对应探针。
- 不固定单一输入：探针输入需要定期轮换，避免渠道针对固定样例做特殊处理。
- 校验输出内容：不仅校验 HTTP 状态，还要校验响应结构、内容、资源链接、任务状态。
- 记录成本：探针自身也会产生消耗和成本，需要单独归因。
- 可灰度执行：高成本视频探针可低频执行，文本探针可高频执行。

#### 8.5.3 探针类型

文本探针：

- 简单问答探针：验证基础响应。
- 格式遵循探针：要求返回 JSON 或固定结构。
- 多轮消息探针：验证上下文处理。
- 流式探针：验证首 token 和流式完整性。

图片探针：

- 文生图探针：验证任务创建、生成结果和资源可访问性。
- 图生图探针：验证输入图片处理能力。
- 尺寸/质量探针：验证不同参数档位。

视频探针：

- 文生视频探针：验证任务创建、轮询、完成和资源可访问性。
- 图片生视频探针：如渠道支持。
- 时长/分辨率探针：验证关键参数是否生效。

#### 8.5.4 探针校验维度

- HTTP 状态码。
- 平台响应解析是否成功。
- 上游错误码是否异常。
- 必填字段是否完整。
- 文本结果是否非空、非模板化、符合基本语义。
- 图片/视频资源 URL 是否可访问。
- 图片/视频文件大小、格式、时长是否符合预期。
- 延迟是否超过阈值。
- 实际消耗是否异常偏高。

#### 8.5.5 探针频率

建议首期默认频率：

| 能力 | 默认频率 | 说明 |
| --- | --- | --- |
| 文本 | 每 1-5 分钟 | 成本低，适合高频健康验证。 |
| 图片 | 每 15-30 分钟 | 成本中等，关注任务成功率和资源可用性。 |
| 视频 | 每 1-6 小时 | 成本较高，按渠道重要性调整。 |

频率可按渠道、模型、成本、重要等级单独配置。

### 8.6 告警管理

#### 8.6.1 目标

平台需要对健康异常、消耗异常、成本异常、预算风险、探针失败等事件及时告警，尤其要防止异常大额消耗造成资金损失。

#### 8.6.2 告警类型

健康类：

- 渠道错误率超过阈值。
- 渠道连续超时。
- 渠道连续探针失败。
- 渠道状态变更为 unhealthy。
- 没有可用渠道可承接某能力或模型。

消耗类：

- 应用请求量突增。
- token 消耗突增。
- 图片/视频任务数突增。
- 单请求消耗异常过高。
- 短时间内重复请求疑似循环调用。

成本类：

- 小时成本超过阈值。
- 日成本超过阈值。
- 月预算使用率达到 50%、80%、90%、100%。
- 单请求成本超过阈值。
- 探针成本异常。
- 渠道单价配置异常导致成本突增。

账户/额度类：

- 渠道余额低于阈值。
- 渠道额度即将耗尽。
- 上游返回余额不足。
- 上游账号鉴权失败。

#### 8.6.3 异常大额消耗保护

平台需要提供成本保护机制：

- 支持按应用设置小时、日、月成本阈值。
- 支持按单请求设置最大成本预估阈值。
- 支持按能力类型设置成本上限，例如视频单任务上限。
- 当预估成本超过阈值时，可以拒绝请求或要求走审批。
- 当实际成本超过阈值时，立即告警并可自动限流。
- 当短时间内成本增速异常时，进入保护模式。

保护模式可执行动作：

- 告警但不拦截。
- 限制 QPS。
- 禁止高成本能力。
- 禁止指定应用继续调用。
- 仅允许白名单业务继续调用。
- 切换到低成本渠道或低成本模型。

#### 8.6.4 告警通知

告警通知需要支持：

- IM 群通知。
- 个人通知。
- Webhook。
- 邮件。
- 值班升级。

每条告警至少包含：

- 告警标题。
- 严重等级。
- 影响范围。
- 应用、渠道、模型、能力类型。
- 当前指标值和阈值。
- 最近趋势。
- 推荐处理动作。
- 相关日志和详情页链接。

#### 8.6.5 告警生命周期

告警状态：

- firing：触发中。
- acknowledged：已确认。
- muted：已静默。
- resolved：已恢复。
- closed：已关闭。

告警需要支持：

- 去重。
- 聚合。
- 抑制。
- 静默。
- 升级。
- 处理备注。
- 事后复盘记录。

## 9. 管理后台需求

### 9.1 首页仪表盘

首页展示：

- 当前平台总 QPS。
- 今日请求量。
- 今日成本。
- 今日错误率。
- 健康渠道数量/异常渠道数量。
- 当前告警数量。
- 成本排行 Top 应用。
- 错误排行 Top 渠道。
- 最近异常事件。

### 9.2 渠道管理

需要支持：

- 新建、编辑、停用渠道。
- 配置渠道凭证和基础地址。
- 配置能力类型和模型映射。
- 配置权重、优先级、限流、超时。
- 配置探针用例。
- 查看渠道健康、消耗、成本和告警。

### 9.3 应用管理

需要支持：

- 新建应用和应用凭证。
- 配置可访问能力和模型。
- 配置应用限流。
- 配置预算和成本保护。
- 查看应用用量、成本、错误、请求日志。
- 支持凭证轮换。

### 9.4 请求日志

日志查询需要支持：

- 按 trace_id/request_id 查询。
- 按应用、渠道、模型、能力类型过滤。
- 按状态、错误码过滤。
- 按时间范围过滤。
- 查看请求元信息、路由结果、上游错误、消耗、成本。
- 敏感内容脱敏展示。

### 9.5 报表导出

需要支持导出：

- 应用成本日报/月报。
- 渠道成本报表。
- 模型消耗报表。
- 告警记录。
- 探针结果。

## 10. 权限与安全

### 10.1 鉴权

- 每个应用使用独立 API Key 或内部服务凭证。
- 支持凭证启用、停用、轮换和过期时间。
- 支持按应用配置可访问能力、模型和渠道。

### 10.2 数据安全

- 请求和响应内容默认脱敏存储。
- 可按应用配置是否保存请求/响应正文。
- 凭证、上游 key、密钥需要加密存储。
- 管理后台操作需要审计日志。
- 敏感操作需要二次确认或审批。

### 10.3 审计

审计日志记录：

- 渠道配置变更。
- 价格规则变更。
- 路由策略变更。
- 预算阈值变更。
- 应用权限变更。
- 人工启停渠道。
- 告警静默和关闭。

## 12. 非功能需求

### 12.1 可用性

- 平台自身不可成为单点故障。
- API 网关需要支持水平扩展。
- 路由配置变更需要支持快速生效。
- 关键配置需要支持回滚。

### 12.2 性能

- 文本同步接口的平台额外延迟目标：P95 小于 50ms，不包含上游耗时。
- 路由决策需要在毫秒级完成。
- 日志和指标写入不得阻塞主请求链路。
- 大流量场景下支持异步落库和批量写入。

### 12.3 可观测性

- 每个请求必须有 trace_id。
- 支持链路追踪。
- 支持指标看板。
- 支持结构化日志。
- 支持从告警跳转到相关请求和渠道详情。

### 12.4 可扩展性

- 新增渠道时应优先通过适配器扩展，不修改核心路由逻辑。
- 新增标准格式时应复用内部标准请求对象。
- 新增成本规则时应保留历史价格和计算版本。

## 13. MVP 范围

首期建议优先交付：

1. 应用鉴权和统一 API 网关基础能力。

3. 渠道管理、模型映射、权重路由和主备切换。

图片和视频能力可在 MVP 后半阶段或第二阶段补齐完整适配和成本规则。

## 15. 验收标准

### 15.1 API 统一接入

- 业务方可以使用统一入口完成文本 API 调用。
- 平台可以将不同标准格式转换为内部请求对象并路由到目标渠道。
- 上游响应可以转换回调用方请求的标准格式。
- 上游错误可以归一为平台错误码。

### 15.2 健康度管理

- 平台可以展示每个渠道的成功率、错误率、延迟和探针结果。
- 当渠道连续异常时，平台可以自动降权或摘除。
- 当渠道恢复后，平台可以通过探针和灰度流量逐步恢复。

### 15.3 消耗量管理

- 每次调用都有 request_log 和 usage_record。
- 文本 token、图片数量、视频时长等消耗可以按应用、渠道、模型统计。
- 上游未返回消耗时，平台可以标记估算值。

### 15.4 成本管理

- 管理员可以配置渠道和模型价格。
- 平台可以按请求生成成本记录。
- 可以查看应用、渠道、模型维度的成本趋势。
- 达到预算阈值时可以触发告警或保护动作。

### 15.5 探针管理

- 平台可以按频率执行探针。
- 探针能校验状态码、响应结构、内容和资源可访问性。
- 探针连续失败可以影响渠道健康状态。

### 15.6 告警管理

- 错误率、探针失败、预算超限、异常大额消耗可以触发告警。
- 告警可以通知到指定人员或群组。
- 告警状态可以被确认、静默、恢复和关闭。

## 16. 待确认问题

1. Jev 标准格式的完整入参、出参、错误码和流式协议定义。
2. OpenAI Completions 与 Responses 需要兼容的具体字段范围。
3. Anthropic Messages 需要兼容的工具调用、多模态、流式事件范围。
4. gptimage、nanobanana、grok 图片格式的字段差异和内部优先级。
5. seedance、minimax-h3 视频格式是否统一为同步提交 + 异步轮询模型。
6. 内部应用是否需要多租户隔离，是否存在部门级预算。
7. 告警通知优先接入哪些渠道。
8. 是否需要审批流来处理高成本请求或预算超限请求。
9. 请求/响应正文的保存策略和脱敏规则。
10. 成本结算是否需要区分真实上游成本和内部转嫁成本。

## 17. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 上游协议频繁变化 | 适配器维护成本增加 | 适配器模块化，增加协议版本字段和兼容测试。 |
| 上游不返回准确消耗 | 成本计算不准确 | 使用平台估算并标记 estimated，后续与账单对账修正。 |
| 图片/视频探针成本高 | 探针自身产生明显费用 | 降低频率，使用低成本参数，单独归因探针成本。 |
| 异步任务重复提交 | 产生重复成本 | 引入幂等键和任务状态表，重试前检查任务状态。 |
| 路由策略过于复杂 | 难以排查问题 | 首期保留少量明确策略，记录每次路由命中原因。 |
| 告警过多 | 值班人员疲劳 | 告警聚合、去重、静默和分级升级。 |

## 18. 成功指标

- 内部业务新增 AI API 接入时间明显下降。
- 渠道异常自动切换成功率提升。
- 异常大额消耗发现时间缩短到分钟级。
- 成本可归因比例达到 95% 以上。
- 关键渠道健康状态可观测覆盖率达到 100%。
- 业务方可自助查看自身用量和成本。
